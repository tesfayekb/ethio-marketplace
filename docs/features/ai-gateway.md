# AI gateway — Foundations turns 15–19

This project's "AI gateway" is its own module over its own provider keys (DEC-248), distinct from the Lovable AI Gateway SDK.

## One call

`src/server/ai/gateway.ts` orchestrates `aiCall(taskId, material, ctx, images?)`. The task lookup is the only step outside the audited try; everything after it — rendering, the model name, the input hash, the D158 gate, the stand-in flag, the provider's key, the caller's reservation, the images, the material supplier, the stand-in or the provider, the parse, the spend — runs inside one try whose every exit writes the content-free audit row, and a rejection anywhere is `unavailable` with its row. It returns success with `{ value, fake, latencyMs }`, or `featureOff`, `budget`, `unavailable`, `timeout`, `providerError` (with HTTP status), `unusableAnswer`, or `reserved` (the caller's reservation refused: no model was asked, no spend, no audit row — the one exit without one). Spend is recorded only for a billed answer (a 2xx, including an unusable one, or a stand-in).

The order is key-first (turn 17, CHANGE 1): the gate answers on, then `fake = standInMode(task.fakeFlag)`; when not fake and the task's provider has no key, the answer is the task's declared `noKey` (`"featureOff"` or `"unavailable"`, default `"unavailable"`) with its audit row and no reservation — a keyless tool never spends a seller's try. Then `ctx.reserve?.({ fake })`, then the images, then the material.

`tasks.ts` registers `name_check`, `category_icon`, `writing_helper`, `photo_screen`, `background_removal` and `category_image`, each with a literal id — `TaskId` is the registry's union and `OutputOf<T>` the task's inferred schema type, so an unknown id is a compile error (AIG-14) and `taskOf`'s one cast sits at that trust boundary. Output objects refuse or strip unknown keys so none survives (GWC-4); seller-name `of` is trimmed and capped at 80 characters, icon names at 60, the writing helper's title and description clamp to 120/1200 before their bounds, the screen's evidence at 200. The registry checks unique ids, known features and deadlines no longer than 120 seconds.

`template.ts` renders the declared fields in order by kind (turn 16): `text` and `lines` are a person's words, always one quoted string (`lines` keeps single line breaks); `list` quotes each item on its own `- ` line under the label, capped at `maxItems`; `code` is a value the field's own `allow` (a RegExp or a literal list) accepts, written unquoted, otherwise the field's `fallback`. An empty optional field with `none` writes `<label>: (none)`. The instruction closes with `withUntrustedRule` exactly once. No person's words become instructions; no String.replace filling.

## Images and image answers (turn 17)

Image material rides beside the text. A task declares `images: { max, maxBytes, min?, all?, lowDetailAfterFirst? }` (CHANGE 3): the gateway type-allowlists (JPEG/PNG/WebP) and bounds size and count before the call; with `all`, one image that would be dropped fails the call BEFORE the provider is asked, logged `image <n> dropped: <why>` — a task that must see every image is never asked with fewer; `min` likewise. `lowDetailAfterFirst` is a Gemini adapter capability (D165): every image after the first carries `mediaResolution: { level: "MEDIA_RESOLUTION_LOW" }`, and a 400 naming the setting is retried once without it, logged as today. An empty rendered user text sends the images alone. The audit hash covers the rendered text and each sent image's byte length and SHA-256.

Material and images may be suppliers (CHANGE 2): resolved once, after the reservation and (for material) after the images, so a caller defers a read it needs only for a real call — the screen's category name, the cut-out's signed cover link — and material derived from the images (the writing helper's photo count) reads true. A stand-in never touches the network.

A second provider and an image answer (CHANGE 4): `provider: "gemini-text" | "gemini-image" | "photoroom-segment"`. `providers/photoroom.ts` (DEC-249: own code over `upstream`, no vendor SDK) posts the image only — multipart `image_file`/`format=webp`/`channels=rgba`/`size=hd`, the key in `x-api-key`, one deadline across headers and body — and answers an image only when the content type is image/png, image/webp or image/jpeg and the body is 1 byte to 8 MiB; any other 2xx is `unusable` and metered (the provider charged for it). The gateway parses an image answer with the task's image output schema; an image answer is never rendered as text (GWC-8).

## The stand-in switch

`standInMode(flag)` in `src/server/stand-in.ts` (DEC-249) is the one stand-in switch: a stand-in exists only in the E2E build, and only when its own flag or the harness-wide `E2E_FAKE_TRANSLATE` is set; a normal build answers false whatever the environment says (INC-828). Every stand-in reader calls it — the AI tasks through the gateway, the category images, the translations. The geocoder's `E2E_FAKE_GEOCODE` is not an AI call and stays outside the AI census by design. SIN-1…3 hold the census and the build gate (INC-828/INC-839, ids unchanged).

One deadline spans the headers and the body read: a deadline passed during the body read is `timeout`; any other thrown read is an answered-but-unusable provider (billed).

## Audit and retention

`audit.ts` awaits service-only `ai_record_call` before returning. `ai_calls` records feature, task/version, model, actor UUID or NULL, the SHA-256 input hash, outcome, provider status or NULL, latency and fake status. No prompt, material, provider body or key is stored. An audit failure logs once without changing the answer. Actor and provider-status RPC parameters are omitted by conditional spreads when null, using M2's trailing `DEFAULT NULL` arguments; generated types are not hand-edited.

DEC-247 retention is enforced in `public.ai_calls_prune()`: rows older than 90 days are purged daily at `17 4 * * *` UTC. Every run writes `ai_calls_prune_runs`, including zero deletions; heartbeats older than 14 days are purged. Both tables and functions are closed to browser roles. An admin last-calls reader remains a later task.

M1 `f5f6c8fb` declares mark `20261025140000`; operator-ruled M2 `71ad0a58` declares `20261025150000`, replaces the unused audit signature with nullable trailing defaults and keeps the same INSERT body and service-only ACL. Both projects hold both marks per operator read-back.

## Translation (turn 19)

Three providers: `provider: "gemini-text" | "gemini-image" | "photoroom-segment" | "google-translate"` (Gemini's text and image adapters, Photoroom, Google Translate). `providers/google-translate.ts` (DEC-249: own code over `upstream`) has two calls. `translateBatch({ target, texts, timeoutMs, label })` posts one form body to Cloud Translation v2 with `source=en` (the catalogue's base language — K4's recorded exception), `format=html`, one `q` per masked text and the key in `x-goog-api-key` only (INC-829), with one deadline across headers and body; it answers `texts` (one per input, `null` where the provider gave none), `unusable` for a 2xx whose body does not parse or whose count differs (metered), or the shared `status | timeout | network | noKey`. `providerLanguages({ timeoutMs })` reads the supported targets (code, English name) once per process, with a deadline.

`translate-tokens.ts` holds the masking rules moved byte for byte from the route (pure, no I/O): each `{token}` travels as `<span translate="no">⟦i⟧</span>`, is restored by index whether the provider keeps or strips the span, and a missing or duplicated sentinel hands the provider's text back for the writer's validator to flag; `decodeEntities`; and the stand-in `fakeTranslate` (`⟪<lang>⟫ <source>`, E2EBREAK drops every placeholder).

The `translation` task: feature `translations`, model env `GOOGLE_TRANSLATE_MODEL` (fallback `v2-nmt`, an audit label only), 20-second deadline, no instruction and no fields (the texts are data, never a prompt), material `{ target, texts }` (a code `^[a-z]{2,8}(-[a-z]{2,8})?$` and at most 100 texts — the gateway answers `unavailable` for anything else), output `z.array(z.string().nullable())` whose length must equal the texts sent (`validate(value, material)`, the material beside the answer since turn 19), stand-in flag `E2E_FAKE_TRANSLATE`. `units` (new): a task may declare `units(material)`; the gateway records it instead of 1 on a billed call — a translation meters the characters it sent, as the route did before.

`translationLanguages({ path })` (gateway export) answers the provider's list, or today's `FAKE_LANGUAGES` (moved byte for byte into tasks.ts) under the stand-in with `fake: true`; it is a free metadata call — no gate, no meter, no audit row; a missing key answers `noKey`, any other failure `unavailable` with one log line.

The gate's mark (ruling R2 on turn 19's stop 1): the answers `aiCall` builds from the gate — `featureOff`, `budget`, and `unavailable` when the switch could not be read (a gate read that throws included) — carry `gate: true`; no other answer does. A caller that must tell "switched off" from a failed call keys on it (translate.ts's first chunk).

## Category image answer (turn 18)

`category_image` uses `gemini-image`, model env `GEMINI_IMAGE_MODEL` with fallback `gemini-3.1-flash-image`, and a 60-second deadline across headers and body. `geminiImage` sends one user text and both TEXT/IMAGE response modalities, without systemInstruction. It decodes the first inlineData once, reads PNG/JPEG/WebP type from magic bytes rather than provider declarations, and refuses missing, unsupported or over-8-MiB images as billed unusable answers.

`promptMode: "inline"` joins the instruction, one untrusted rule and rendered material. A text field's fixed `fallback` writes the marketplace root for an empty parent; person-supplied category and parent names remain quoted. `renderTask` exports the exact text sent; successful answers carry measured `latencyMs`. The captured stand-in is pinned by AIG-35 (8,884 bytes, decoded SHA-256 and every PNG CRC). BGR-13 likewise pins the restored cut-out (INC-879). AIG-36 clears both provider keys before every test; real-path tests set their own keys (INC-880).

POST and GET generate-image use defineRoute with categories:assets and strict shapes in schemas/category-image.ts. They read the category and home parent as the caller before aiCall. Unknown categories remain 404. POST returns generated/prompt/genMs/base64; GET returns raw bytes, their read type, X-Gen-Ms and no-store. Both use fixed failure words; no provider text escapes the probe. CIR-1…6 cover authority, read order, switch mapping, provider mapping, probe and customPrompt rejection. Legacy gate/provider/prompt/fixture files are retired. The browser uses callRoute's 30-second budget, then preserves canvas variants, session uploads, persistence and pruning; generation_prompt is always NULL.
