## 0 · Purpose and era shape
**Purpose (operator, 2026-09-15).** The marketplace serves places where a specific population concentrates — Ethiopians first. The location list is therefore a curated map of where our communities live and trade, not a gazetteer; a seller advertises where they are by default and may widen to more cities, states or countries (paid later); a visitor is placed by their IP, sees what is near them first, and the feed widens by itself — nearest first, always, never a click, never a question, every listing showing where it is. Very light, secure, performant.
**Shape.** Serial landings, one prompt in flight (§3): **G0** governance import → **L1a** schema + trigger + permissions + admin RPCs (Tier A migration) → **L1b** import family planner/commit/undo (Tier A migration) → **L1c** public tree read + version (Tier B migration + one server route) → **L2** console + E2E (Tier A: admin panel) → **L3** the files — countries, Ethiopia-deep tree, diaspora seed (curator loop, operator imports; no executor turn) → **L4a** geo-guess A7 spike → **L4b** shell consumption + saved area (Tier B) → era gate (four-lens review; `name_am` totality proven; column drop stays a later, separate destructive migration on operator go). Every feature ships its E2E green before the era closes (G13/G15). Records land verbatim in a docs paste after each code verification; every prompt opens with step 0.

## 2 · Laws of the era (do not re-derive)
1. **Tree law.** One canonical tree, four levels, strict parent step: `country → region → city → sub_city` (region = state/province/regional state). No zones/woredas. Every row carries its ancestors as columns — `country_code`, `region_id`, `city_id` — filled by the ancestry trigger, so every location question is an indexed equality, never a walk; coverage rows and the feed copy the same four columns.
2. **Concentration law.** City nodes are metro-scale (Atlanta is the metro; Marietta, Decatur, Alpharetta are its aliases); `sub_city` serves kifle ketema (Addis Ababa) and later any metro whose listing density earns it. The tree is the union across communities (Minneapolis enters once, for Somalis or Ethiopians); expanding to a community = places + a language, zero schema. A place absent from the tree is a decision, not a gap.
3. **Country law.** `public.countries` is the reference root and the country profile; the tree's country row is only the anchor (created by activation if missing). `countries.is_active` means the **market is open**: its tree visible, posting into it allowed, present in the shell picker. Identity is not a market: `confirm_home_country` keeps reading every seeded country — a user in Lagos states Nigeria before the Nigerian market opens.
4. **Visibility law.** A node is visible ⇔ it and every ancestor are active, evaluated in the tree read (one WHERE; no cron, no cascading writes). Activating under an inactive parent is refused by name; deactivating a parent hides its subtree by the path rule. Listings, coverage rows and profiles keep their FKs regardless (P2-a law); hard delete only with no children and no references, else `retireInstead`.
5. **Naming law.** `name_en` is the source; every other language lives in `entity_translations` (`'location'`, `name`). The import's `name_am` cell is a carrier (IE-4a: an `edited` human row through the translation door, undone with the batch); the console links other languages to Translations → Data. The reader already resolves through `entityName`; the era makes the `name_am` column fallback unnecessary (L4b's payload carries `name_en` only; the gate asserts every active Ethiopian location has an approved am row). `locations.name_am` retires with `categories.name_am` in one later destructive migration on explicit operator go.
6. **Aliases law.** `aliases text[]` carries name variants — suburbs of a metro, Latin/Ge'ez spellings (Adama/Nazret, Bishoftu/Debre Zeit, Hawassa/Awassa, Mek'ele/Mekelle) — matched for the IP guess, the picker search and future fuzzy search; never displayed as labels.
7. **Seed and curation law.** Geography lands by **file through the one import gate**, never by migration (REQ-005: a city is an admin action, never a code change). The curator authors the files offline from GeoNames (CC-BY 4.0 — one attribution line in `/docs` and on the about page) on this spec's laws; this thread validates by preview counts; the operator commits. Nothing gazetteer-like ships in the app or the database (S24 stands; apex's 55 KB static lists are the counter-example). **Cadence:** the tree is reviewed with the curator on a routine — every quarter and at every market opening — fed by the U6 request queue and the DEC-058 inbox; a one-off city is the console's add form.
8. **Country profile law (DEC-055 first landing).** `unit_system` (`metric` | `imperial`), `currency_code` (ISO 4217; REQ-018 poster default; rates/conversion = DEC-056 at U7), `display_order`, `country_root_order` (per-country order of ROOT categories; absent = global rail; REQ-023's cold-start override, honoured as a pin by any later learner). Recorded: at home Vehicles · Real Estate · Electronics lead; abroad Food · Fashion · Beauty · Real Estate · Travel lead.
9. **Coverage law (DEC-064 candidate; supersedes the July one-country rule as a hard law).** A listing's coverage is a set of nodes at any level (`listing_locations`): "all of Oromia" is one row. Default = the poster's own area; the posting form prefills preferred posting location → last listing's location → the IP guess, always editable (apex's initialisation order). **Limits are admin-set per advertisement type** (promotion tier per REQ-024: `free` first; `classified`/`premium` are new rows): `max_cities`, `max_regions`, `max_countries`, `allow_everywhere` — seeded `free = 1 / 1 / 1 / off`, changed in the console without code. "Everywhere" is one worldwide coverage record, allowed only when the plan says so. Posting (U6-A) enforces the plan server-side by counting coverage nodes per level and distinct countries; A2's one-country trigger retires then by named DEC. All free in v1; the tiers are how coverage pricing attaches later with zero rework.
10. **Guess law (DEC-063 candidate).** The starting area is a first guess from the edge's request geo facts (Cloudflare: country, region code, city) — no third-party IP API, no edge function (INC-096), no data leaving. Mapping to the curated tree: country by code → region by `iso_3166_2` → city/sub-city by slug or alias → else the deepest level that matched; nothing matched = no guess, never a default (§7 banned pattern). The guess is recomputed per request (free) and **never persisted** as a fact — `country_source` stays `ip_guess`/`unknown`; it is never a security input.
11. **Stream law (DEC-065 candidate; U7 builds it, this era guarantees its inputs).** The feed is one continuous stream, not a tier that switches: the viewer's area nearest-first, then the rest of the region, then the rest of the country, then worldwide — each section honestly labelled ("Rest of Georgia"), every card showing its place, no question and no click; a category with two items in the city shows those two first, then the state's; Montana with nothing near starts at the country section. Match: a listing belongs to a section when a coverage node contains the scope or the scope contains it (four nullable equalities on the ladder columns). Nearest-first by center distance, always. The era guarantees: coordinates on every city and sub-city, the distance function, the ladder columns; the manual override outranks the ladder; if it yields nothing the user is told and offered the next level.
12. **Persistence law.** The saved area always wins over the guess. Anonymous and signed-in alike: a preference cookie `ethio_area` (the chosen node id only, set on the user's explicit pick, one year, `SameSite=Lax`, read on the server like `ethio_lang_star`) so the first paint renders at the saved place with no flash and no location query; signed-in users additionally get `profiles.browse_location_id` at U7 for cross-device. The guess is never written to the cookie or the profile (law 10). One line in the REQ-034 ToS/Privacy source ledger (a preference cookie for a user-chosen place, no personal data).
13. **Weight law.** One small ETag'd JSON per country (ET ≈ 300 rows ≈ 15–25 KB gzipped — ESTIMATE), 304 on repeat visits; the device resolves the guess against the cached tree; opening the app costs zero location queries; the public path never calls `has_permission`; no extension, no dependency, no static lists.

## 3 · Data model deltas (all additive; L1a unless noted)
- `locations`: `level` CHECK widened to `('country','region','city','sub_city')`; `+ region_id uuid NULL REFERENCES locations(id)`, `+ city_id uuid NULL REFERENCES locations(id)` (ancestor columns, trigger-filled, never client-written); `+ display_order int NOT NULL DEFAULT 0`; `+ iso_3166_2 text NULL` (regions; unique where not null); `+ aliases text[] NOT NULL DEFAULT '{}'`; `+ source text NOT NULL DEFAULT 'admin' CHECK IN ('seed','admin','import')` (U6 adds `'user'` + `submitted_by` with the request door); **coordinates law**: `CHECK (level IN ('city','sub_city') = (center_lat IS NOT NULL AND center_lng IS NOT NULL))` after the shallow seed is completed by file (the migration proves the current 18 cities carry coordinates before adding the constraint, else names the rows). Indexes: `(country_code, is_active)`, `(parent_id)`, `(region_id)`, `(city_id)`, `(iso_3166_2)`.
- `countries`: `+ unit_system text NOT NULL DEFAULT 'metric' CHECK IN ('metric','imperial')`, `+ currency_code char(3) NULL CHECK (~ '^[A-Z]{3}$')`, `+ display_order int NOT NULL DEFAULT 0`, `+ updated_at timestamptz` (+ trigger). Profile values ride the L3 countries file.
- New `country_root_order (country_code FK, category_id FK, position int, PK(country_code, category_id), UNIQUE(country_code, position))` — deny-all client RLS; one audited definer writer; roots only.
- New `coverage_plans (plan text PK, max_cities int NOT NULL, max_regions int NOT NULL, max_countries int NOT NULL, allow_everywhere boolean NOT NULL DEFAULT false, updated_at, updated_by)` — CHECK all ≥ 1; seed `('free', 1, 1, 1, false)`; public SELECT (posting reads it), writes via one audited definer RPC gated by a new resource `coverage` (`view` / `update`, `update` requires step-up).
- New `location_import_revisions` (L1b; mirrors `category_import_revisions`).
- `geo_distance_km(lat1, lng1, lat2, lng2) RETURNS double precision` IMMUTABLE SQL (haversine; no PostGIS — REQ-003, A2b precedent), with a proof row (Addis→Adama ≈ 75 km ± 2).
- `get_location_tree_version(p_country)` derived from `max(updated_at)` over the country's rows and the country row (L1c) — no new table.
- **Ancestry trigger** `locations_ancestry_guard` BEFORE INSERT OR UPDATE: parent exists; `level = parent.level + 1` (country ⇔ parent NULL); `country_code = parent.country_code`; fills `region_id`/`city_id` from the parent chain (a region's `region_id` is itself for children to copy; NULL on its own row); slug `^[a-z0-9]+(-[a-z0-9]+)*$`; re-parenting keeps the level rule (no cycle expressible); an active row cannot have an inactive parent; a country row's `country_code` exists in `countries`; coordinates law above.
