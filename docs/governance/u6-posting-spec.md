## 0 · Purpose and era shape
**Purpose.** A seller posts in about two minutes on a cheap phone: category → photos → specifications → title/description → price → where → contact → review; nothing is asked twice, nothing is asked before it matters; every word and image is screened by one gateway before it is live; drafts survive a dropped connection; expired or sold posts return with one tap. Trust is the product: no fabricated claims, no unscreened input, no phantom success.
**Shape (serial landings; migration parts before code where DEC-023 parity demands).** **G1** governance import → **A1** schema: the posting read, validation authority, capabilities, price period, search column, home-country truth (Tier A migration) → **A2** the draft door: `submit_listing` re-declared whole (draft upsert, server-derived home country, coverage counted against plans, A2 trigger retired) + the listing revision table (Tier A migration) → **B1** photo pipeline server side: strip route + storage variants law + deny-proof (Tier A) → **B2** photo pipeline client side (Tier B) → **C1** the wizard, steps 1–4 (Tier B) → **C2** steps 5–8 + draft autosave + review/publish (Tier B) → **D1** the screening gateway + states + rate limits (Tier A migration + route) → **D2** the human review queue console (Tier A admin) → **E1** My Listings (Tier B) → **E2** expiry scheduler + reminders + renew/relist (Tier A ops) → era gate (four-lens review; launch-gate items). Every feature ships its E2E green (G13/G15); records land in docs pastes after verification.

## 2 · Laws of the era (do not re-derive)
1. **Floor law (REQ-020).** A post needs category · title · price mode (where the category prices) · location · contact preference; photos and description are optional; the flow is one screen per step at 360, back is free, nothing is lost (autosave).
2. **Single writer.** `submit_listing` is the ONLY write path for a listing's content (drafts included) and `transition_listing` the only state changer; the gateway is the only judge; the CI listing-write seam guard stays.
3. **Residency truth (three facts, one rule).** `user_directory.observed_country_code` = the edge's country at the seller's FIRST contribution, set by the server, never editable, admin-visible; `home_country_code` = the country the user declares at the first posting (confirm-or-edit thereafter; editable in Settings; never a separate prompt), used for defaults — currency, units, rail — and shown on the profile; every listing's partition key `home_country_code` is set by the server to the country observed at THAT post (`residency_country_for(user, request)`), never to the declared value and never from the client. Observed ≠ declared is a review signal, never a block. The rule lives in one function so counsel's ruling (Q-014) can change it without moving data. One physical partition at launch (operator ruling 2026-09-16; REQ-033 amended): the key is carried from day one so the Ethiopia split on the licensing trigger is a copy by predicate, never a redesign.
4. **Category decides.** The category decides pricing (`price_enabled`, `default_price_period`), expiry (`expiry_days`), restriction (`is_restricted` → screening tier), capabilities (`bookable`, `map_pin`), the specification form (effective links, cards, required), and the illustration for photo-less posts.
5. **Validation authority (DEC-051).** `validate_listing_attributes(category_id, attrs)` is the only authority for attribute values; the client mirrors for UX only; `attrs` is typed, `other` stored as `{ value: "other", text }`.
6. **Price law (REQ-018 + census).** One amount, one currency (default = the seller's home-country currency), one mode, one **period** (once · hour · day · week · month · year; the category's default, changeable where the category allows); money never floats; ranges (salary, budget) are attributes, never a second price; free/contact carry no amount.
7. **Coverage law (DEC-064).** Coverage = `listing_locations` rows at any level within the plan (`free` = 1 city / 1 region / 1 country, no everywhere); the item's own place is `listings.location_id` (the first coverage row); the editor is bounded live and the door counts per level and distinct countries; A2's one-country trigger retires in the same migration that enforces plans. Prefill: preferred posting place → last listing's place → the shell's guess.
8. **Photo law (REQ-019/036, DEC-009; storage per DEC-075).** Every write goes through a storage adapter that routes by partition (one partition at launch; rest-of-world on Cloudflare R2 via the S3 API from the strip route; keys `<partition>/<user_id>/<listing_id>/<photo_id>/<variant>`; the database stores partition + key, never a provider URL). Max 10 (dial), first = cover; the client resizes and compresses on device (long edge ≤ 1600, ~200–400 KB) and produces the card and thumb variants (480 / 160, WebP where supported); **every stored image passes the server strip route** — an allowlist re-writer that keeps only image data segments (JPEG APPn/COM/XMP dropped; WebP EXIF/XMP/ICC chunks dropped; PNG ancillary text chunks dropped) with real-format verification by magic bytes — proven by a deny-proof fixture with GPS before any upload ships; `exif_stripped = true` is set only by that route; photo-less posts show the category illustration, never confusable with a real photo. **Video link (operator 2026-09-16):** one optional YouTube URL per listing, validated to the YouTube shape and stored as a URL only — never hosted, never embedded in the feed; the card shows the thumbnail and the player loads on tap through the no-cookie domain; the URL is screened like text.
9. **Screening law (REQ-021/022, three-tier).** Every listing goes draft → **screening** → live | reduced-reach | rejected (with appeal) | held for review; one gateway route screens text, attributes and images with structural validation → sanitisation → file inspection → content-policy model; the model's verdict is auto-applied only above confidence thresholds (dials), the rest lands in a human queue; a restricted category always lands in the queue; every verdict is audited with the model, version and rationale; nothing user-typed ever renders as HTML. **Enforcement (REQ-009/010/011, operator 2026-09-16):** human involvement is the exception — confident violations auto-reject and, when already live, auto-remove; a seller accrues strikes (`seller_standing`) that shorten allowances (drafts per day, live count) and suspend posting at a dial; a model or rule update re-screens live posts in a sweep and removes confident violations retroactively; user reports feed the same queue (U8); every automatic action carries an appeal path.
10. **Grounded-only text (REQ-020; July lock amended 2026-09-16).** Optional AI assistance for title and description from day one, tested in E2E through a deterministic fake: the assist may only organise facts the seller gave (category, attributes, photos' declared facts); it never adds quality claims; the seller accepts, edits or writes their own; the screening model judges readability and category coherence and flags, never rewrites.
11. **Rate-limit law (REQ-038b).** Per-action limits are one primitive (`rate_limits` table + `consume_rate_limit(action, key)`), applied to post/draft, edit, photo upload, report, message, resend; refusals name the window; limits are dials per action; no limit is enforced client-side only.
12. **Search-ready law (REQ-038a).** `listings.search_tsv` (weighted title/description/attribute text, language-aware where possible) is maintained by trigger from day one so U7 search never rebuilds the schema.
13. **Lifecycle law (REQ-022).** Expiry = earlier of the poster's date (optional) and the category default; reminder before expiry; one-tap renew (heartbeat); sold strips contact but stays visible until expiry/removal; expired/sold stay in My Listings for relist; edits of a live post re-enter screening; every content change writes a `listing_revisions` row (who/when/what).
14. **Contact law (REQ-007/020).** Contact preference is a profile-level shape — in-app messages always; phone / Telegram / WhatsApp optional — chosen at the first posting and shown confirm-or-edit thereafter; the listing stores only the choice; numbers render only to signed-in viewers and never after sold; v1 sellers are personal (alias + contacts; storefronts are REQ-008's era).
15. **Weight law.** The wizard is its own route chunk; the map pin loads only for categories with the `map_pin` capability and only on that step; option lists arrive lazily per definition, version-cached (DEC-053); no new dependency unless named (Leaflet + the tile provider are named for the pin, loaded on demand).

## 3 · Data model deltas (additive; A1 unless noted)
- `listings`: `+ video_url text NULL CHECK (YouTube shape)`; `+ price_period text NOT NULL DEFAULT 'once' CHECK IN (once,hour,day,week,month,year)`; `+ poster_expires_at timestamptz NULL`; `+ search_tsv tsvector` (trigger-maintained; GIN index); `+ screening jsonb NULL` (last verdict summary: tier, confidence, flags, reviewed_by); `status` CHECK widened to `draft · screening · active · reduced · rejected · held · expired · sold · removed`; `+ contact_pref jsonb NOT NULL DEFAULT '{}'` (the chosen channels for this listing); `+ cover_photo_id uuid NULL`.
- `categories`: `+ capabilities text[] NOT NULL DEFAULT '{}' CHECK (allowlist: bookable, map_pin)` (DEC-052) — a seller-level shop pin ("sold from my store") arrives with storefronts (REQ-008) and every listing may inherit it then; `+ default_price_period text NOT NULL DEFAULT 'once'` (same CHECK); `+ price_period_locked boolean NOT NULL DEFAULT true`; both exported/imported as cells in the categories file.
- `user_directory`: `+ observed_country_code char(2) NULL` (the edge's country at the first contribution; server-set once; admin-visible) and `+ observed_at timestamptz`; `+ standing jsonb NOT NULL DEFAULT '{}'` (strikes, restrictions, since); the signup path passes the L4 guess as `country_guess` (source `ip_guess`) so the declared value starts pre-filled; `residency_country_for(user_id, request_country)` (definer) returns the partition key for a post.
- `profiles`: `contact_prefs` shape law: `{ messages: true, phone?: { number, show }, telegram?: { handle, show }, whatsapp?: { number, show } }`, validated server-side; `+ preferred_post_location_id uuid NULL` (the prefill; `default_post_location_id` from A3 is renamed by view, not dropped — census the reads first).
- New `listing_revisions (id, listing_id, seller_id, kind create|edit|state, before jsonb, after jsonb, actor uuid, created_at)` — deny-all client RLS; written by the doors.
- New `screening_verdicts (id, listing_id, tier auto_live|auto_reject|held|human, verdict, confidence numeric, flags jsonb, model text, model_version text, rationale text, reviewer uuid NULL, created_at)` — deny-all client RLS; admin read via RPC.
- New `rate_limits (key text, action text, window_start timestamptz, count int, PK(key, action, window_start))` + `consume_rate_limit(p_action, p_key, p_limit, p_window)` (definer; server routes call it).
- New reads (definer, anon+authenticated where public): `get_posting_schema(p_category_id)` → the category's flags and its effective attribute links with definitions (type, required, order, card_rank, bounds, presets, `other` allowed, option COUNT — options themselves lazy), `get_attribute_options(p_attribute_id)` (DEC-053, version-cached by the route `/api/attributes/$id/options`), `get_listing_draft(p_listing_id)` (owner), `list_my_listings(p_status)` (owner), `get_coverage_plan(p_plan)`.
- Doors (definer, F5): `submit_listing` re-declared WHOLE (A2) — draft upsert (autosave), typed `attrs` via `validate_listing_attributes`, coverage rows validated against the plan, `home_country_code := user_directory` (the caller's value ignored; a mismatch is a refusal), price law, period law, poster expiry, `contact_pref` shape, `search_tsv`, revision row; `publish_listing(p_listing_id)` → draft→screening and the gateway call; `transition_listing` re-declared with the new states; `renew_listing`, `mark_sold`, `relist_listing`, `set_cover_photo`, `register_listing_photo` (only the strip route's service call may set `exif_stripped`); `admin_review_listing(p_listing_id, p_verdict, p_note)` (step-up; `listings:review`).
- Permissions: resource `listings` gains `view · review (step-up) · enforce (step-up)`; `admin.roles.perm.*` keys ride the landing (D2).

- **D7 Photos and video.** Hidden metadata (GPS, device, timestamps) stripped on the server before storage by keeping only image data — no server image library; the three sizes made on the phone; one optional YouTube link per listing, shown as a thumbnail, played on tap, never hosted. *Ruled 2026-09-16.*

- **D9 Tags** at U7; brands as attributes. *Ruled 2026-09-16.*
