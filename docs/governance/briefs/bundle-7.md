The rule being replaced, as the code stands (step-specifications.tsx):
- `dependents` (:776–789) is every detail that has a show-when condition or that ANY option's facts or bounds mention. `parents` (:804–822) is every picker whose options carry facts or bounds, every fold owner, and the card-1 identity. `roots` (:831–835) is the identity alone.
- When a parent's answer moves (:948–952): if it is the identity changed from one answer to another, the scope is EVERY other definition (the whole form starts over — D25b, D46, D47); otherwise the scope is `[...dependents].filter(key => !parents.has(key))` — every dependent detail on the form, whichever parent it depends on — and each is re-derived from the merged facts of all chosen options (`facts.prefill`): a fact refills it, no fact means the link's default or empty. So a change of one parent can empty a detail that depends on another parent, or on a condition only.
- Then the narrowing pass (:1014 on; INC-244) clears a choice the options now on offer no longer hold.

A1. THE RULE, as a pure function with unit tests, red-first.
New file src/features/posting/reset-scope.ts, no React in it. It answers two questions from the definitions and options the form already holds; step-specifications.tsx calls it and keeps no second copy of the logic.
DEPENDS ON. Question D depends on question P when at least one of these holds:
 1. D's options hang under P's options — P is D's fold owner (today's `folds`, :557–588);
 2. an option of P carries a fact for D (`option.facts[D]`, a list fact included; today's `facts.byOwner`, :678–726);
 3. an option of P carries a bound for D (`option.bounds[D]`, or a bound written inside `facts`);
 4. an option of P carries an `allowed` list for D (today's `narrowing`, :598–612);
 5. D's show-when condition names P.
Nothing else makes a dependency: not sharing a step, not form order, not a card rank, not being the identity.
WHAT A MOVE OF P DOES. "P moved" is what it is today: the seller gave P an answer different from the one it held, a first answer included (INC-329 unchanged: joining the parent set is not a move; a parent emptied by the pass itself is not a move). For each D that depends on P, in form order:
 1. D is not asked under the answers as they now stand (its condition is not met): D stores nothing (INC-257, unchanged).
 2. The NEW option of P carries a fact for D: D takes that fact as a prefill, exactly as a prefill is written today (it stays editable; a tick-box gets the hint beside it, never a tick — D27 unchanged).
 3. Otherwise, D's answer was written by the form and the seller left it as it was (the key is in `prefills` and the answer still equals what was written — today's `fromModel`, :1443–1444): it belonged to the old choice and goes with it — D returns to its link default, or to empty when the link has none (INC-245 unchanged).
 4. Otherwise D holds the seller's OWN answer: it is KEPT when it still fits and CLEARED when it does not. "Fits" is decided only by what the catalogue states, never by a guess: a choice fits when it is among the options the question now offers (`visibleOptionsOf` — fold parent, allowed lists, active options); a multi-select keeps the picks that fit; a number or a year fits when it lies inside the bounds now in force (`boundsOf`); a text, a tick, and any answer no rule speaks about, fits.
FOLLOWED THROUGH. When the pass changed D's answer and D is itself a parent, the questions that depend on D are treated the same way, and so on down; a question is visited once per pass. A question that does not depend on P, directly or through such a chain, is NOT READ AND NOT WRITTEN by the pass — whoever filled it.
THE IDENTITY IS A PARENT LIKE ANY OTHER. The whole-form restart is retired: `roots` and `rootChange` go; a first answer and a change follow the one rule above (DEC-139 is absorbed). On a leaf whose identity carries no fact, no bound, no allowed list, is nobody's fold owner and is named by no condition, changing it changes nothing else.
UNDO. Unchanged: when the pass changed anything, the ten-second offer restores the snapshot of answers and prefills; when it changed nothing, no offer appears.
THE NARROWING PASS stays. It is the same "fits" rule for choices; after this part the two must agree — the report says in one line whether the pass still clears anything rule 4 did not already clear, and what.
