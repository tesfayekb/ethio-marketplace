PART D — THE ROUTE CLIENT. NEW src/lib/route-client.ts:
`export type RoutePath` — the template-literal type of a string that begins `/api/` (written with a backtick template and `string`); · `export type RouteAuth = "required" | "optional" | "none";` · `export type RouteAnswer = { kind: "answered"; status: number; ok: boolean; payload: Record<string, unknown> | null; error: string | null; detail: string | null } | { kind: "signedOut" } | { kind: "unreachable"; reason: "network" | "timeout" | "aborted" };` · `export type RouteInit = { method?: "GET" | "POST" | "PUT" | "PATCH" | "DELETE"; json?: unknown; auth?: RouteAuth; timeoutMs?: number; signal?: AbortSignal };`
`export async function callRoute(path: RoutePath, init?: RouteInit): Promise<RouteAnswer>` — auth defaults to "required"; reads the session through the browser client (src/integrations/supabase/client.ts) once; `Authorization: Bearer <token>` only when a token exists; `Accept: application/json` always; `Content-Type: application/json` and `JSON.stringify(json)` only when `json` is given; method defaults to GET without a body and POST with one; the deadline per CHANGE (3); a thrown fetch maps to `unreachable` (`TimeoutError` or the deadline's own abort → "timeout", the caller's abort → "aborted", anything else → "network"); a JSON answer (content type contains `application/json`) is parsed — an object becomes `payload`, anything else `null`; `error` and `detail` are the payload's string fields or `null`. Never logs the token, the headers or the body.
`export async function downloadRoute(path: RoutePath, filename: string, init?: { auth?: RouteAuth; timeoutMs?: number; signal?: AbortSignal }): Promise<RouteAnswer>` — the same call; on `ok` it saves the answer's bytes under `filename` through one object URL and one anchor (created, clicked, removed, the URL revoked) and returns `{ kind: "answered", …, payload: null }`; on a refusal it returns the parsed envelope and saves nothing.
