## 2 · Inventory by phase (exists / partial / missing), grounded
**U6-A schema + draft lifecycle.** Exists: `listings` (title, description, attributes jsonb, price triple, status, home_country_code, published_at, expires_at), `listing_photos`, `listing_locations` (A2, one-country trigger), `submit_listing` (validation stub; takes `p_home_country_code` from the caller), `transition_listing`, `expire_stale_listings`, categories.expiry_days. Missing: DEC-051 `validate_listing_attributes` + `attrs` typed shape (`other` as `{value:"other", text}`), DEC-052 `capabilities[]`, DEC-053 option delivery RPC, `price_period`, poster-set expiry, a `search_tsv` column (REQ-038a: FTS at launch, no rebuild later), `submit_listing` re-declared (home country from the profile; coverage counted against `coverage_plans`; A2 trigger retired; autosave = draft upsert). Apex parallel: `listing_versions` (change history) — ours is the revisions/audit pattern already used by imports.
**U6-B media.** Missing entirely: on-device resize/compress (~1600 px), server-side allowlist EXIF/GPS strip with the REQ-036 deny-proof BEFORE any upload ships (DEC-009), variants (cover/thumb/medium — apex `listing_media` shape: width/height, focal point, sort order), bucket policies (private upload, public variants), real-format verification and a moderation hook (REQ-021 layer 3; apex `image_moderation_logs`), max 10 (dial), first = cover. Illustration fallback exists (categories images console).
**U6-C posting form.** Missing: the category-driven form (cards per DEC-043; attestation controls for fact-asserting booleans; units per DEC-055; option lists lazy per DEC-053), the coverage editor bounded by `coverage_plans` (add city / state / country / everywhere), prefill order (preferred → last listing → guess), the contact-preference step (shape law needed), the "my city isn't listed" door (inactive row, screened, reviewed in Places), AI drafting under the grounded-only rule with a fake mode for E2E (the translate route's pattern), drafts autosave.
**U6-D screening gateway (Tier A).** Missing: the one choke point (structure → sanitize → files → content-policy AI), the screening states in the state machine (screening · live · reduced-reach · rejected · frozen), per-action rate limits (REQ-038b: post, message, resend, report, search) as a shared primitive, duplicate-post detection, CAPTCHA seam already threaded (REQ-037).
**U6-E my-listings.** Missing: dashboard, edit (re-screened), one-tap sold (strips contact, stays visible), renew, relist, expiry reminder, scheduler wiring (pg_cron or external).

## 3 · Rulings the U6 spec must record (with recommendations)
- **Tags (REQ-041, C4).** Not a posting prerequisite. Discovery aids for search; the ledger already places them at U7 (tags + per-category suggestions, admin CRUD). Apex's `listing_tags` / `tag_categories` / `listing_tag_assignments` is the shape to adopt then; adding a tag control to the form later changes no listing column. Recommendation: U7.
- **Brands.** WooCommerce has a Brands taxonomy because storefronts merchandise by brand; classifieds (OLX, Jiji, Facebook Marketplace) capture brand as a per-category attribute — which the curation era already did (make/model/year for Vehicles; brand options for Electronics, Fashion, Appliances). A global brand entity buys cross-category brand pages and SEO (v2 seam), not posting. Recommendation: brands stay attribute options; the U6 spec verifies each root that needs brand/condition carries them (a file pass where not).
- **Listing type and price period.** Apex carried `listing_type` + `pricing_model` + `price_period` + rental deposit + salary; WooCommerce has product types. Ours: the category decides the type (a Real Estate rental category, a Jobs category, a Services category) and needs a **price period** (once · hour · day · week · month · year) defaulted per category and a per-category "price required" rule; a salary/price range is an attribute, not a second price. Recommendation: `price_period` + `categories.default_price_period` at U6-A; no `listing_type` column.
- **Contact channels.** The floor needs a contact preference at post time. Recommendation: a profile-level shape (in-app messages always; phone/Telegram/WhatsApp optional with per-listing show/hide), edited in Settings; the listing stores only the choice, never a copy of the number (single writer; sold strips it).
- **Home country (two values, no forced step).** Ratified: no prompt or settings gate before the user has a reason to care; captured inside the first posting flow, confirm-or-edit on later posts, editable in Settings any time (REQ-006; identity-schema "Named deferral"). Two values: `guessed_country_code` — from the edge at signup/first visit, admin-visible, a fraud signal when it disagrees, never the partition key — and `home_country_code` — declared at first posting, the partition key, `country_source = 'user_confirmed'`; the client sends the L4 guess as signup metadata so `ip_guess` finally fills. Apex's split is the same (`profiles.detected_*` from IP at first sign-in; the vendor's preferred location as the declared value; wizard prefill preference → last listing → detected). Landing: columns + signup metadata at U6-A; capture step at U6-C; Settings field at U6-E.
- **Delivery, stock, variations, tax, shipping classes, reviews-at-post** (WooCommerce): out of v1 by DEC-001 and the classifieds model — recorded as not applicable.
- **Moderation before live vs after.** REQ-022 orders draft → screening → live; posts are not visible until the gateway answers. Recommendation: keep it (trust is the product); the gateway's latency budget is a Pass-2 dial.

## 4 · Recommended order (spec work runs ahead of build, §3)
1. **U6 Pass-2 spec session** now, in parallel with the Locations era gate (which waits only on the curator's files) — the spec carries this census, the §3 rulings, the forward-scan of REQ-023–041, and the A–E landing map.
2. **The curator's two location files** proceed in parallel (brief delivered 2026-09-16); the Locations era gate closes on their import and Amharic approval; nothing in U6's spec waits on them.
3. **U6-A → U6-B → U6-C → U6-D → U6-E**, each with its E2E, the REQ-036 deny-proof gating U6-B, the gateway CI guard (no write path bypasses it) gating U6-D; no landing precedes U6-A — the home-country and contact-channel capture live inside the first posting flow by law.
4. Tags at U7 with search; a brand entity, bookings (DEC-052 capabilities) and everywhere-coverage pricing return by their DECs.

## 5 · What apex teaches, kept and refused
Kept: the wizard order (category first, media before pricing, review last); drafts with `draft_saved_at`; per-listing versions for edits; media variants with focal points; moderation logs per image; expiration notifications and renewal counts; grace periods. Refused: 61 loosely typed columns (dimensions, weight, SKU, stock, downloads, sale windows — storefront concerns), free-text city, client-trusted location, moderation status editable outside the state machine, a third-party IP API.
