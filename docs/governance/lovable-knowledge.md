ETHIO.COM — PROJECT KNOWLEDGE · v3.12 (2026-10-29; supersedes v3.11). Rules override conflicting requests.
APP ethio.com: production, mobile-first, multilingual classifieds PWA for Ethiopians and Eritreans at home and abroad. Users post into admin-managed categories; buyers browse geo-scoped feeds and contact sellers. No payments in v1. Low-cost Android, expensive data; Amharic, Afaan Oromo, Tigrinya, English.
ARCHITECTURE TanStack Start (SSR React) + Tailwind. Backend: the CONNECTED EXTERNAL Supabase; publishable key only in the browser; schema truth = /supabase/migrations (append-only). DEC-020: commits land on dev; main advances only by CI's fast-forward promote on green. Pages /src/routes (server endpoints /src/routes/api); features /src/features/<name> (components/, hooks/, <name>-service.ts); primitives /src/components; pure utilities ONLY /src/lib; translations /src/i18n/locales (one lazy file per language); docs /docs (features/<name>.md, _changelog.md append-only). kebab-case files, PascalCase components, use-* hooks; split at ~300 lines.
RULES A. PROCESS A0 CI FIRST: each turn first reads the last COMPLETED CI run (the raw ci-evidence files, AGENTS.md); any red is fixed first, at its root, then the work continues; never end a turn just to wait for CI; the report opens with that CI line. A1 SCOPE: modify only files named in the task; if the task needs others, STOP and say which/why; siblings outside scope are reported (K2), not touched; end by listing every file modified. A2 NO UNSPECIFIED WORK: no demo data, extra pages or refactors; ambiguous → ask. A3 HONESTY: a task you cannot fully do, or a platform limit, is said BEFORE anything changes. A4 CONFLICTS: if a request conflicts with these rules, say so and wait. A5 COMMITS: descriptive, scoped; never secrets; the platform commits when the turn ends. A migration and its files land in the same turn; a lost tree after an apply is reported first. A6 CI-CLEAN: before every push run `bun run checks` (every CI check needing no backend or browser: the harness typecheck verdict, build + page budgets, lint, format, unit tests, guards, i18n maps); fix every FAIL, rerun it whole, paste its last line, name every NOT RUN. New files: git ls-files proof. Migration reports state "apply <uuid-fragment> → expect mark <declared value>" (DEC-022). Reports touching e2e/** end with the J-audit line (+ cleanup-survives-timeout). A7 FIRST-OF-KIND + LOCAL PROOF: a category with no precedent censuses the installed package's export (paste it) and lands a minimal smoke proof. DEC-023/114/119: staging E2E credentials only via the secret dialog; prod credentials never reach the executor; the in-turn E2E run is the spec files changed or added in the turn (bun run e2e:local -- <specs>: both projects, each file whole, 0 retries, summary pasted; e2e:changed when the selector names ≤5 files); a spec file not fully green is not committed; parity-blocked = STOP and report the apply line; CI on the final commit is the full-suite proof.
B. REUSE B1 Search before creating any component/hook/utility/key/table; say what you searched. B2 One utility per concern, in /src/lib. B3 Primitives in /src/components, feature pieces in /src/features; extend via props, never copy. B4 One component per file.
C. MOBILE-FIRST UI C1 Design at 360px first; verify 360/768/1024/1280. C2 Touch targets ≥44px; primary actions near the bottom; nothing relies on hover. C3 Design-system tokens only. C4 Every screen has translated loading/empty/error states; an empty state is a caption beside the controls, never a replacement. C5 RTL-safe: logical properties only (ms-/me-/ps-/pe-/text-start). C6 Accessibility basics; screen-reader-only text is user-visible (D1). C7 Data tables render ONLY through the DataTable primitive: priority tiers + width utilities, cardUntil='lg' when dense; it owns pagination and overflow; minWidth only for unwrappable dense data with a same-line // C7-dense: note; no per-page width hacks; never "[object Object]", undefined or NaN. C8 ONE CONSOLE SHAPE: admin tables are the DataTable primitive with their own toolbar — find and transfer groups as direct children of the toolbar slot, no labels above controls, import/export in the toolbar scoped by its filter; no Tabs; one edit icon per row, verbs in the editor's verb bar (CT-8); related consoles are rail sub-sections under a group page.
D. TRANSLATION D1 No user-visible literal strings; every string is a key from /src/i18n/locales. D2 Every new key ships EN+AM in the same change; a migration registering a permission action ships its admin.roles.perm.* keys too. D3 The DATABASE is runtime truth for UI strings (ui_translations) and entity strings (entity_translations); compiled files are seed + fallback; overlay DB[lang] ▸ compiled[lang] ▸ compiled.en; an empty catalog is invisible; a DB-only language is legitimate. Keys are born in code (Sync keys); publishing is coverage-gated on approved keys and refuses an empty catalog. D5 A RENAMED STRING IS A NEW KEY: changed wording gets a NEW key (the old one retired when unread); editing a key's compiled value never reaches production: an approved DB row outranks the file (D3).
E. DATABASE E1 Every new table ships RLS ENABLED + per-operation policies + explicit GRANTs incl. GRANT ALL TO service_role, after revoking the birth grants from anon/authenticated (INC-212). E2 Migrations append-only; corrections are new migrations; destructive only when the task says so. Never patch a function body by text anchor (INC-183): re-declare it WHOLE (over ~10 KB: computed insertion, md5-guarded) (DROP+CREATE if the return shape changes) with the closers (REVOKE PUBLIC, anon · GRANT EXECUTE authenticated · GRANT ALL service_role) in-file and a definition+ACL read-back. E3 Personal-data tables carry home_country_code; timestamps timestamptz UTC. E4 Money: never floats. E5 GENERATED/EXEMPT: only the files .prettierignore names one by one (never a widened glob; supabase/types.ts is never hand-edited). E6 Totality gates define the empty set explicitly (empty ≠ complete; partial ≠ granted). E7 Client reads only via gated SECURITY DEFINER RPCs; rpc() argument and column names are copied from the SQL declaration; list RPCs ship index + EXPLAIN in the migration proof.
F. SECURITY F1 Secrets never in code/comments/commits; service-role never client-side; server-route secrets read from server env inside the handler (never VITE_). F2 Validate input server-side; render user content as data, never HTML. F3 The server (RLS/has_permission) is the ONLY authority; UI hiding is convenience. F4 No phantom success: failures surface as translated messages and are logged; an errored permission check renders as an error, never "no permission"; a guarded action reports its result even after a step-up round-trip. F5 Writer order in every mutating RPC: gates (permission → step-up → scope) → capture (old→new) → mutate; a refused attempt leaves no trace. Imports follow docs/features/imports.md (cells are data, identities never renamed, read-only columns reported not applied, preview writes nothing, commit idempotent and undoable, step-up gated).
G. PERFORMANCE/SEO G1 Public pages SSR with correct title/meta/og (absolute URLs), declared language, hreflang from the publication gate; public-path DB work is version-cached. G2 No new dependency unless named; images lazy with dimensions; no autoplay or prefetch beyond viewport.
H. DOCUMENTATION H1 Structural changes update /docs/features/<name>.md and append one _changelog.md line in the same change; never renumber or delete. H2 No known-error debt: every violation a check surfaces, even pre-existing, is reported and fixed as a tracked task before the phase closes.
I. RUNTIME STABILITY I1 Fixtures are captured from real tool output, never authored. I2 Ref contract: a Slot/asChild child holds the ref (never a wrapper); no inline state-writing refs on mapped children; ref-fed state uses stable callbacks + equality-guarded writes. I3 Identity stability: hooks never return fresh []/{} into dependency arrays; mirrored writers are equality-guarded; measuring hooks never observe what they mutate. I4 Server routes use the Start primitive; handlers log every throw and deliberate 5xx as "[ssr-error] <path> <message>"; Supabase calls over 5s log "[slow-rpc]". I5 Auth-state callbacks never call Supabase (the auth lock is held); hop a macrotask; first-frame Supabase reads belong to the auth flow alone; core auth code changes only by DEC. Step-up freshness comes from the token (aal2 + totp amr), never a client hint. I6 Gate-list reads: a plain keyed anon fetch, cache:"no-store", never cache-busted by query params; a failed (even thrown) gate fetch is logged and retried once, never silently defaulted. Root providers render immediately, reconcile async; step-up dialogs render on the top layer.

K2 Every report lists each other place with the same concern that bypasses the mechanism (file:line), in scope or not; fix only what the brief covers; no sibling goes unreported. K3 A new mechanism lands with its conformance guard (a census test or lint failing when a consumer bypasses it) in the same landing. K4 No literal language, country, currency or role code in app code or SQL outside the one constants module/function. K5 Every AI call goes through the one gateway (feature switch, budget, prompt template with user text as data, output schema, audit log). K6 Every server route parses input through the shared schema helper (zod); every form through the shared field/validation primitive.
