## Departure: the codes cell

Ruling 2 Part B says the line's codes cell gains `ownListing`. It does not, and the cell stays
`badValue`. `scripts/doors/manifest.ts` defines the cell as "the door's OWN refusal codes besides the
shared gate codes", and the judge (`scripts/doors/judge.ts:160–165`) compares it with the
`door_refuse` calls in the door's own body. DEC-403 puts `ownListing` in the core alone ("the rule
lives in ONE place"), so a cell naming it fails check-doors static:
`class-mismatch admin_review_listing(uuid,text) — codes badValue for the line's badValue,ownListing`.
The siblings take the same form: `admin_move_listing` and `admin_edit_listing` list `-` although their
cores refuse `ownListing`. The reason cell names the core's `ownListing` instead. If the supervisor
wants the cell, the choices are a judge that reads callee codes (a mechanism change) or a second copy
of the rule in the door (against DEC-403); both are the supervisor's.
